# QB Housing integration contracts

The baseline tables below record the pre-implementation audit on 15 October 2026. The implemented additions immediately below supersede those baseline limitations; the original details remain for compatibility review. Caller identity, permissions, and financial success must come from server services, never from UI visibility or a notification.

## Implemented additive contracts

| Resource/API | Contract used by housing | Failure and lifecycle |
| --- | --- | --- |
| qbbanking ExecuteTransaction | `(key,{debits={{citizenid|account,amount}},credits={...},statements={{query,values,expectedRows?}}})` → receipt or `nil,code,message` | Resource allowlist, balanced whole amounts, gross-funds check, immutable request, checked pinned transaction. Player money, named accounts, domain writes, ledger and receipt commit together. |
| qbbanking GetOperation | `(key)` → receipt or `nil,code,message`, scoped to caller | Waits prior SQL worker and publishes confirmed balances through qbcore locks. Pending/indeterminate does not mean declined or completed. |
| qbcore column coordination | begin/finish/abort player-column operations for money/inventory | Persistent fencing excludes ordinary writes, queued saves, offline updates and conflicting character loads until confirmed reconciliation. Existing APIs remain. |
| qbsql checked operations | `QB.sql.transactionChecked(statements,operation?)` → `{success,results?}` or `{success=false,code,message}` | Checks expected row counts before commit. Optional operation identity joins active work and supports restart reconciliation. Legacy transaction API remains unchanged. |
| qbinventory RegisterStashPolicy | `(id,options,callback)` → `true,inventoryId` / `false,reason` | Persists owning/required policy, rebinds restored inventories and closes sessions at the mutation barrier. Missing/stopped policy denies. Busy inventory returns a retryable failure. |
| qbinventory RebindStashPolicy | `(id,callback)` → boolean/reason | Callback-only rebind for the existing owning resource, including an unresolved durable claim. Never saves a stale source snapshot. |
| qbinventory SetStashBlocked | `(id,blocked)` → boolean/reason | Owner-only, confirmed save and transfer barrier; closes sessions and also blocks trusted mutators. Used to hold empty stashes through sale settlement. |
| qbinventory ClaimStash | `(source,id,operationKey)` → `true,receipt` / `false,reason` | Source, player inventory and receipt commit once under inventory and core-column locks. Capacity failure is retryable. Trusted recovery API can deliver remotely while ordinary stash access remains proximity checked. |
| qbgarages RegisterPropertyGarage | `(id,definition,callback)` → boolean/reason; callback `(source,'list'|'store'|'retrieve',id)` | Persistent property registration, disabled until live rebind; server policy and per-vehicle ownership/capacity/storage checks. Public garage callbacks cannot bypass protected garages. |
| qbgarages openGarage | Client `(id)` opens the existing garage UI | Housing first obtains an authorized server garage ID and proximity check; actual garage callbacks independently revalidate. |
| qbdoorlock RegisterDoorPolicy | `(id,callback)` → boolean/reason; callback `(source,id,{lockpick,authorised,door})` | Authoritative for opted-in doors. Clear leaves denied; owner-only ReleaseDoorPolicy explicitly removes housing protection when unlinking. Resource/provider restart closes/rebinds policies. |
| qbinterior createGeometry/removeGeometry | Client geometry creation preserves createShell's result layout without teleport; owner cleanup | Allows nearby observers and multiple occupants to stream coherent scenery. Existing teleporting shell APIs remain. |
| qblib placement | `QB.placement.start(model,{coords?,rotation?,bounds?,raycast?,numericInput?,copy?})`; owner-scoped cancel | Extends existing editor. Existing start(model) and result remain. Preview/model/camera/control cleanup is tested. |
| qbdispatch createCall | Existing call API; explicit trusted qbhousing caller | Persisted alarm cooldown precedes dispatch; failures report that delivery was not confirmed. Optional phone mail never authorizes recovery. |

See each changed resource's README/docs for the complete additive API surface. Housing's actual registered routes are in server/main.lua and verified against every client call site by tests/contracts.lua.

No API in this table provides a durable cross-resource bank-plus-property commit today. `QB.sql.execute` returns a result table containing affectedRows, insertId, changedRows, and warningStatus; `QB.sql.update` returns affected rows. Use `QB.sql.NULL` for deliberately null positional parameters. `savePlayer` confirms enqueue, not SQL commit. Named account balances return zero for a missing account too, so check existence separately. There is no verified offline personal-bank debit API.

## Camera and shared space limitations

qbbusinesses CCTV supplies callouts and hack/repair metadata, not live rendered feeds; its hacking workflow uses a private bucket and is unsuitable for shared housing viewing. The qblib freecam is a local scripted viewpoint.

OneSync culls distant players/entities, while the streaming focus native describes terrain rendering. Therefore a camera position change alone cannot establish an arbitrary-distance live occupant feed. This is an engineering inference that needs a multiplayer prototype, not a verified streaming capability. See the official [OneSync documentation](https://docs.fivem.net/docs/scripting-reference/onesync/) and [streaming focus native](https://github.com/citizenfx/natives/blob/master/STREAMING/SetFocusPosAndVel.md).

Within one shared physical space, occupants and camera viewers must see a coherent furniture set. Property IDs still independently identify permissions, money, stashes, and leases. Distinct private layouts at identical coordinates require a changed rendering policy or distinct physical origins; no buckets are proposed.

## Historical integration changes identified by the audit

| Resource | Minimum required capability | Existing behavior to preserve |
| --- | --- | --- |
| qbcore and qbbanking | Durable operation key, confirmed receipt/status lookup, gross-funds check, online/offline serialization with ordinary money writers, and confirmed bank/society settlement | Existing money exports, taxes, player data, bank UI and society account APIs |
| qbsql if needed | Verified Lua transactional bridge with expected-row checks and rollback before commit | Current query/execute/transaction signatures and error behavior |
| qbinventory | Resource-owned stash access policy registration/rebind with persisted required-policy marker; confirmed durable recovery transfer/receipt boundary | Existing stash/provider signatures, contents, session validation and ordinary inventories |
| qbgarages | Runtime property garage registration/update/removal, server policy on list/store/spawn, garage identity/capacity, validated entity lifecycle | Existing public/job/gang/legacy garage semantics |
| qbdoorlock | Opt-in authoritative housing door policy with stable door ID and fail-closed behavior when housing unavailable | Existing grant hooks and unrestricted/nonhousing door behavior |
| qblib placement | Optional initial transform/bounds, scripted-camera raycast positioning, shared numeric entry and gameplay confirmation | Existing `start(model)` editor, result shape, cancellation and cleanup |
| qbinterior | Geometry-only shell creation without its existing automatic teleport, for nearby occupants and camera viewers | Existing createShell/named-export signatures, returned handles, model release and default entry teleport |
| qbdispatch | Explicit trusted qbhousing caller and approved alarm payload configuration | Existing callers and dispatch contracts |

These changes add capabilities to the established integrations. They do not authorize replacing them with independent housing inventory, banking, garage, UI, or instance systems.
